# Permintaan perubahan untuk repo Maung-Wo-Inv (tempel ke sesi Claude repo tersebut)

Dua perubahan kecil, kompatibel mundur, supaya CRM (maung-crm) dapat menumpang di VM yang sama dan menautkan Closed Won ke pelanggan/FAB. Aturan seperti biasa: Bahasa Indonesia, identity thuekx tanpa trailer Claude, hanya branch main, uji sungguhan sebelum push, jangan tambah fitur di luar yang diminta.

1. **Export API — resource baru `GET /api/export/subscriptions` (baca-saja)**, autentikasi, paginasi `cursor`/`limit`, dan filter `since` (berdasar `createdAt`) sama seperti resource `customers`. Kolom: `regNo`, `formDate`, `name`, `phone`, `packageName`, `source` (MANUAL/RADIUS), `marketingName`, `customerCode` (dari `Subscription.customerId` → `Customer.code`), `woNumber` (dari `woId` → `WorkOrder.number`), `createdAt`. Jangan keluarkan data finansial (biaya) kecuali sudah termasuk di ekspor lain. Dokumentasikan di `docs/API.md` dan tambah tes.

2. **Pastikan `GET /api/export/customers` memuat** `code`, `name`, `phone`, `status`, `radiusStatus`, `salesName`, `createdAt`, dan `areaName` bila ada (tambahkan yang belum ada saja); filter `since` berdasar `createdAt` dipertahankan. CRM memakainya untuk mencocokkan Opportunity Closed Won dengan pelanggan baru dari MSRadius.

3. **Caddy: dukung situs tambahan dari berkas.** Caddyfile awal (`proxy/Caddyfile.init`) dan Caddyfile yang ditulis ulang API (Admin → Pengaturan → SSL & Domain) harus menyertakan baris `import /etc/caddy/sites/*.caddy` (di level atas, setelah blok global), dan `docker-compose.caddy.yml` memasang `./proxy/sites:/etc/caddy/sites:ro` pada service `caddy` (buat `proxy/sites/.gitkeep`). Tujuannya: aplikasi lain di VM yang sama (CRM di `crm.<domain>` → `crm-web:3000` lewat jaringan Docker bersama) cukup menaruh satu berkas `.caddy` tanpa tertimpa penulisan otomatis. Pastikan penulis Caddyfile di API mempertahankan baris import itu, tambah tes, dan dokumentasikan di `docs/INSTALL.md` / `docs/SUPER-APPS.md`. Jangan ubah perilaku domain WO yang ada.
